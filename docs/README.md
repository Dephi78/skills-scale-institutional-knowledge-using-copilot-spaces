# OctoAcme Project Management Documentation

## Overview

This directory contains the complete OctoAcme project management framework and process documentation. Use these guides to understand our approach to planning, executing, and delivering projects that consistently deliver customer value through clear ownership, iterative delivery, and data-informed decision-making.

## Core Principles

OctoAcme's project management approach is built on five foundational principles:

- **Customer-first**: We prioritize customer value and usability in every decision
- **Iterative delivery**: We deliver small, testable increments rather than big-bang releases
- **Clear ownership**: Each project has a named Project Manager and Product Lead with defined accountability
- **Data-informed decisions**: We measure impact and iterate based on evidence, not assumptions
- **Psychological safety**: We encourage feedback, learning, and continuous improvement across all levels

## Project Lifecycle

OctoAcme projects follow a structured five-phase lifecycle:

1. **Initiation** → Validate the problem statement, align stakeholders, and confirm business need
2. **Planning** → Break work into shippable increments with clear acceptance criteria and dependencies
3. **Execution** → Build, test, review, and iterate with daily standups and continuous communication
4. **Release** → Deploy to production with verification, monitoring, and stakeholder communication
5. **Close & Retrospective** → Capture learnings, celebrate wins, and identify improvements for future projects

## Core Roles & Responsibilities

OctoAcme projects operate with clearly defined roles that ensure accountability and smooth execution:

- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success
- **Developers**: Implement features, collaborate on design, and ensure code quality
- **QA/Testing**: Validate quality and confirm acceptance criteria are met
- **Stakeholders**: Provide inputs, approvals, and business context

For detailed role descriptions and responsibilities, see [Roles and Personas](./octoacme-roles-and-personas.md).

## Communication Cadence

Consistent communication keeps all stakeholders aligned:

- **Daily standups**: 15-minute team syncs focused on progress, blockers, and dependencies
- **Weekly PM sync**: Alignment between Project Manager and Product Manager
- **Weekly delivery sync**: Team shows progress, updates, and flagged risks
- **Monthly stakeholder updates**: High-level status and key decisions
- **Ad-hoc escalations**: When blockers require immediate attention

## Quick Start Guide

**New to OctoAcme?**  
Start with [Project Management Overview](./octoacme-project-management-overview.md) to understand our principles, roles, and key artifacts.

**Starting a new project?**  
Follow the [Project Initiation](./octoacme-project-initiation.md) guide to validate business need and get stakeholder alignment.

**Managing day-to-day work?**  
Reference [Execution & Tracking](./octoacme-execution-and-tracking.md) for standups, PR workflows, quality gates, and blocker escalation.

**Preparing to release?**  
Consult [Release & Deployment](./octoacme-release-and-deployment.md) for pre-release requirements, deployment checklists, and rollback procedures.

**Completing a project phase?**  
Use [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md) to capture learnings and identify improvements.

**Facing risks or dependencies?**  
See [Risk Management & Communication](./octoacme-risks-and-communication.md) for risk registers, escalation paths, and stakeholder communication strategies.

## Key Artifacts by Phase

- **Initiation**: Project One-pager, Stakeholder list, Risk list
- **Planning**: Release plan, Sprint backlog, Definition of Done, Risk register, Dependency map
- **Execution**: Project board (GitHub Projects), PR descriptions with acceptance criteria, Test results
- **Release**: Release notes, Deployment checklist, Post-deploy verification results
- **Retrospective**: Retrospective notes, Action items, Improvement tracking
